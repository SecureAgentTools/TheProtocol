# The sidecars a frame is wired into (§ONESHOT P2.2, 2026-09-12)

A frame stood up by `scripts/hetzner_demo/standup_driver.py` needs four things that are not part of the
frame: something that scrapes it (Prometheus + vmalert), an independent auditor that reads its ledger
(`Agents/TheAuditor`), a federated index with its own identity (`directory/`), and a host-side refresh
of its SPIRE trust bundle (`scripts/deploy/frame-spire-bundle.sh`, a cron, because host nginx must
reload). `--wire-prod` writes the frame's slot into each of them through ONE manifest.

- `sidecars.json` names where each piece lives on THIS host (theprotocol-srv1: the live auditor,
  directory and Prometheus projects, the bundle lists, the SNI script, the apex vhosts).
- `sidecars.json.example` is the manifest of a host that runs `docker-compose.sidecars.yml` instead.
- `docker-compose.sidecars.yml` is that project: Prometheus (file_sd: one JSON per frame in
  `prometheus/targets/`), vmalert (`vmalert/rules/`), the auditor and the directory, built from this tree.
  Copy `env.sidecars.example` to `.env.sidecars` (600), `docker compose -f docker-compose.sidecars.yml up -d`.
- `scripts/hetzner_demo/sidecars.py`: `require` (sentences for what is missing), `status`, `unwire <stack dir>`
  (the frame's own slot out of every artifact; the teardown script calls it first).
- The bundle refresh is registered per frame and builds ONE federated client-CA file PER IDENTITY NET
  (`bundles.federated_by_net`): a sandbox pair's roots never enter the production pair's file.

A host without a piece is refused with a sentence naming it, before anything is written:

    python3 scripts/hetzner_demo/sidecars.py require --apex

## §FRAMEKIT P3.1 (2026-09-12) — what a frame ships for its own observability

- `sidecars.json` names `prometheus.query_url` (and, when the host has one, `metrics_store.url`): the
  driver writes them into the frame's env as `PROMETHEUS_URL` / `VICTORIA_METRICS_URL` under `--wire-prod`,
  and every network join carries the aliases the registry's code defaults resolve (`prometheus`,
  `victoriametrics`). Without them the status page has no history (the flagship measured 0 of 90 days).
- `prometheus/targets/<frame>.json` (file_sd): each target carries its own `job` label — the names the
  status page keys history on — so the one `frames` job never shows up as a job of its own.
- `vmalert/rules/frames.yml`: the frame-generic rules (component down, registry down, the auditor's Δ,
  auditor stale, card-pull stale, balance outbox backlog, treasury low = page, workers failing
  persistently, peers unreachable). Every metric named there is exported by a live frame; thresholds
  are measured, not guessed. No ledger-freshness rule: a quiet network is not a defect.
- `alertmanager/alertmanager.yml`: the routes, `page|critical` FIRST (§PAGEROUTE). Receivers ship with no
  integration: name yours, or alerts are dropped in the open (`amtool config routes test` shows where).
- `grafana/provisioning/`: the Prometheus datasource (uid `DS_PROMETHEUS`) and `Frames/frame-overview.json`,
  generated by `scripts/hetzner_demo/frame_dashboard.py` (`--queries` prints every panel expression so a
  proof can run each against Prometheus for a live frame).
- `python3 scripts/hetzner_demo/sidecars.py reconcile` after ANY recreate of Prometheus, the metrics store
  or the auditor: compose recreates a container with its compose networks only, and every frame network
  joined by wire() is gone with it (the §pass23 storm). `status` shows what reconcile would do.
- `python3 scripts/hetzner_demo/sidecars.py wire <stack dir> --only prometheus [--operators a,b]` wires a frame
  that predates a piece.
- ⚠ modes: git keeps no file modes and this tree's umask writes 640 — `chmod -R a+rX sidecars/` after a
  checkout, or the containers cannot read their mounts (Prometheus runs as nobody).
