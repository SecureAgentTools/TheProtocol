# Network profiles — the one place every money amount lives (§MONEY-M2)

## Why

Every sizing residue in the money inventory is the same defect wearing a different number: an amount
written for a billion-token supply, hardcoded or defaulted at its call site. R7 (grant), R8 (operator
seed 100,000), R11 (presence threshold), R12 (prices, caps, seven request ceilings), R13 (canary
fires), R17 (sim seeds), R27 (correction ceilings), R29 (showcase float). On a network whose whole
supply is a few hundred thousand units, a 100,000 operator seed is not a seed — it is the economy.

They are not eight pieces of work. They are eight rows of one file.

## The three rules

1. **Env wins.** A profile value is a *default*. Anything already set in a compose file or an
   `.env.*` carrier overrides it. Adding a profile can never move a number a node already states.
2. **No profile selected ⇒ nothing changes.** With `NETWORK_PROFILE` unset — the state of every node
   today — each call site falls back to the literal it always had.
3. **`mainnet-2026` is a recording, not a proposal.** It is generated by reading the running fleet.
   It exists so the fresh network has something to diff against.

Precedence, in one line: `os.environ` → profile file → the caller's `fallback=`.

## Files

| file | what it is |
|---|---|
| `config/network_profile.mainnet-2026.env` | today's fleet, measured. Regenerate, never hand-edit. |
| `network_profile.lowsupply-2026.env` | **not yet written — it needs decisions D1 and D2** (see below) |
| `../scripts/network_profile_knobs.py` | the knob table: name, reader file:line, code default, fresh-net formula |
| `../scripts/render_network_profile.py` | renders either profile |
| `src/agentvault_registry/core/network_profile.py` | the loader the code calls (`money_knob`, `int_knob`, `bool_knob`, `knob`) |

## Regenerating the recording

```
python3 scripts/render_network_profile.py mainnet -o config/network_profile.mainnet-2026.env
```

Each knob is annotated with where its value came from — `env:<container>` or `code-default` — so a
reader can tell a deliberate setting from an accident of the source.

## The fresh network

```
python3 scripts/render_network_profile.py lowsupply \
    -o config/network_profile.lowsupply-2026.env --s0 <S0> --grant <GRANT>
```

**The renderer refuses without both.** `S0` (the initial issuance per frame) is decision **D1** and the
grant is **D2**; they are the Commander's, and nothing in this repo invents a value for either.
Every other amount is then computed as a fraction of those two, so the whole economy moves together
when he changes one number. Change S0 or the grant and re-render — never hand-edit an amount.

## Using a profile on a node

```yaml
environment:
  NETWORK_PROFILE: lowsupply-2026      # a bare name is looked up in /app/config
  # NETWORK_PROFILE: /app/config/network_profile.lowsupply-2026.env   # or a path
```
The profile file must be present in the image or bind-mounted at `/app/config`.

## Adding a knob

1. Add a row to `scripts/network_profile_knobs.py` — including the `reader` file:line, which is
   checked.
2. Read it at the call site through `money_knob(NAME, "<today's literal>")`. The literal stays as the
   fallback: that is what makes the change inert until a profile is selected.
3. Re-render `mainnet-2026`.

`tests/test_network_profile_parity.py` fails if a knob in the table is read nowhere in the tree, so
the file cannot rot into a list of names nothing consults.

## What the profile deliberately does NOT own

Fees (0.5 % base / 5 % velocity-scaled, cross-registry 0.5 %) are ratios, not amounts — they are
already supply-independent and zero-sum. Authority flags (IRONKEY modes, delegation, spawn anchor,
contracts x-frame) are not money. Secrets never appear here; this file is tracked.

## Where these files live, and why

They sit inside `agentvault_registry/` rather than at the stack root because the registry
Dockerfile's `COPY ./agentvault_registry/ .` then lands `config/` at **`/app/config`** — the path the
loader already searches — with no Dockerfile change and no bind mount.

`scripts/` is the opposite case: `.dockerignore` excludes `agentvault_registry/scripts` (§EXCISION),
so the knob table and the renderer stay in the repo and out of every shipped image. That is correct —
they are authoring tools, not runtime.

⚠ When excluding `.env` files from the image (R37), exclude the **root** `.env` only. A blanket
`**/*.env` would silently drop `config/network_profile.*.env` out of the image and every knob would
fall back to its code default with nothing to say so.
